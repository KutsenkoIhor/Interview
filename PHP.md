### 1. Що таке never type у PHP, для чого він використовується і в яких випадках його доцільно застосовувати?

<details>
<summary>Розкрити:</summary>

#### Відповідь

`never` — тип повернення (з PHP 8.1), що означає: функція **ніколи не повертає контроль виклику**. Вона або кидає виняток, або викликає `exit()`/`die()`, або містить нескінченний цикл. Якщо функція з `never` спробує виконати `return` — fatal error.

Це не `void`. `void` означає «повертає, але без значення». `never` означає «виконання після виклику цієї функції не продовжиться».

```php
function throwNotFound(string $message): never
{
    throw new NotFoundException($message);
}

function redirectAndExit(string $url): never
{
    header('Location: ' . $url);
    exit();
}
```

**Навіщо потрібно статичному аналізатору (PHPStan/Psalm):** коли аналізатор знає що функція `never` повертає, він розуміє що код після її виклику недосяжний. Це усуває хибні попередження «змінна може бути null»:

```php
function getUser(int $id): User
{
    $user = $this->repo->find($id);
    if ($user === null) {
        throwNotFound("User {$id} not found"); // never
    }
    return $user; // аналізатор: $user точно User, не null|User
}
```

**Де доцільно:** helper-функції для кидання типових винятків (`throwUnauthorized`, `throwValidationError`), `assertNotNull`-обгортки, термінальні методи роутера або bootstrap.

#### Міні-шпаргалка

- `never` = функція не повертає контроль (throw або exit)
- Відрізняється від `void`: void повертає без значення, never не повертає взагалі
- Допомагає статичним аналізаторам усунути хибні "can be null" warnings
- З PHP 8.1+

</details>

### 2. Яка система типів використовується в PHP, які у неї переваги та недоліки?

<details>
<summary>Розкрити:</summary>

#### Відповідь

PHP використовує **динамічну типізацію з опціональними анотаціями типів**. Змінні не мають оголошеного типу — тип визначається значенням в момент виконання. Параметри функцій, повернені значення і властивості класів можуть анотуватись типами, які PHP перевіряє в runtime.

**Динамічна типізація:**
```php
$x = 1;       // int
$x = "hello"; // string — та сама змінна, інший тип
$x = [];      // array
```

**Опціональні анотації:**
```php
function add(int $a, int $b): int { return $a + $b; }
// Без strict_types=1: add("2", "3") → 5, не помилка
```

**Переваги:**
- Швидкий старт, прототипування без багатослівності
- Гнучкість при обробці різнорідних даних (legacy JSON, API відповіді)
- Поступова типізація: можна анотувати критичні ділянки і залишати `mixed` де не критично

**Недоліки:**
- Без `strict_types` неявні приведення маскують помилки
- PHPStan ефективний лише якщо типи реально анотовані
- Складніше рефакторити великі кодові бази без типів

#### Міні-шпаргалка

- PHP — динамічна типізація + опціональні type hints
- Тип перевіряється в runtime (не compile-time як у Java/Go)
- Без `strict_types` — coercive mode: PHP сам приводить типи
- Повноцінна типобезпека: `strict_types=1` + PHPStan level 9 + typed properties

</details>

### 3. Для чого використовується declare(strict_types=1) і як це впливає на поведінку PHP-коду?

<details>
<summary>Розкрити:</summary>

#### Відповідь

`declare(strict_types=1)` перемикає файл з **coercive mode** (PHP сам приводить типи) на **strict mode** (тільки точний тип, інакше `TypeError`). Діє лише на файл де оголошено — не глобально.

**Без strict_types (coercive mode):**
```php
function add(int $a, int $b): int { return $a + $b; }

add("3", "4");      // → 7, PHP мовчки привів рядки до int
add(3.9, 4.1);      // → 7, float → int (втрата дробової частини!)
add("3 apples", 4); // → 7, PHP обрізав не-числову частину
```

**З strict_types=1:**
```php
declare(strict_types=1);

add("3", "4");  // TypeError: must be of type int, string given
add(3.9, 4.1);  // TypeError: must be of type int, float given
```

**Важливий нюанс:** `strict_types=1` у файлі A впливає на виклики **з файлу A**. Якщо файл B без strict_types викликає функцію з файлу A — coercive режим (з точки зору виклику B).

**Чому важливо:** `add("abc", 5)` без strict повертає `5` замість помилки; `add(99.9, 0.1)` → `99` — непомітна втрата даних.

#### Міні-шпаргалка

- `strict_types=1` → TypeError замість мовчазного приведення
- Діє на файл де оголошено (не глобально)
- Без нього `"3"` → `int(3)`, `3.9` → `int(3)` автоматично
- Має бути першим рядком після відкриваючого тегу PHP

</details>

### 4. Чому питання типів у PHP особливо важливе при роботі з великими числами, приведенням типів і неявними перетвореннями?

<details>
<summary>Розкрити:</summary>

#### Відповідь

PHP приховує кілька пасток що проявляються лише на реальних даних і можуть призвести до фінансових помилок або втрати даних.

**Float не є точним числом.** IEEE 754 подвійна точність:
```php
var_dump(0.1 + 0.2 === 0.3); // bool(false)
var_dump(0.1 + 0.2);         // float(0.30000000000000004)
echo 10.00 * 0.07;           // 0.7000000000000001
```
Для грошей — тільки `bcmath` або зберігати суми в цілих числах (копійки/центи).

**Неявне приведення в порівняннях (`==`):**
```php
var_dump(0 == "foo");   // true (PHP 7) — рядок "foo" → int 0
var_dump("1" == "01");  // true — обидва як числа
var_dump(100 == "1e2"); // true — наукова нотація
var_dump("" == null);   // true
```
PHP 8 покращив: `0 == "foo"` → `false`. Але завжди краще `===`.

**Приведення типів з втратою:**
```php
(int)"99 bottles" // → 99, мовчки відкидає " bottles"
(int)"bottles"    // → 0
(int)null         // → 0
(int)9.99         // → 9 (не 10!)
```

**Великі числа і json_decode:**
```php
// Snowflake ID більший за PHP_INT_MAX на 32-bit
$data = json_decode('{"id": 99999999999999999}');
// $data->id → float з втратою точності!

// Рішення:
$data = json_decode('...', false, 512, JSON_BIGINT_AS_STRING);
```

**Правила виживання:**
- `===` замість `==` — завжди
- `bcmath` або `brick/money` для фінансових операцій
- `filter_var($val, FILTER_VALIDATE_INT)` для валідації замість `(int)$val`
- `json_decode` з `JSON_BIGINT_AS_STRING` для зовнішніх API з великими ID

#### Міні-шпаргалка

- `float` не точний: `0.1 + 0.2 !== 0.3` → bcmath для грошей
- `==` з числом і рядком → небезпечне приведення; завжди `===`
- `(int)"99 bottles"` → 99 мовчки; `(int)null` → 0
- PHP 8: `0 == "foo"` → false (фікс), але `===` надійніше
- Великі числа: `json_decode` + `JSON_BIGINT_AS_STRING`

</details>

### 5. Що таке type hinting у PHP, як він працює і навіщо потрібен?

<details>
<summary>Розкрити:</summary>

#### Відповідь

Type hinting — оголошення очікуваного типу для параметрів функції, повернутого значення і властивостей класу. PHP перевіряє типи в runtime при виклику.

```php
function greet(string $name): string
{
    return "Hello, {$name}";
}

class User
{
    public function __construct(
        public readonly int    $id,
        public string          $name,
        public ?string         $email = null,   // nullable
    ) {}
}
```

**Що можна анотувати:**

- Скалярні: `int`, `float`, `string`, `bool`
- `array`, `callable`, `iterable`
- Класи та інтерфейси: `User`, `DateTimeInterface`
- `self`, `static`, `parent`
- `void`, `never`, `mixed`
- Nullable: `?string` ≡ `string|null`
- Union: `int|string` (PHP 8.0+)
- Intersection: `Countable&Iterator` (PHP 8.1+)
- DNF: `(Countable&Iterator)|null` (PHP 8.2+)

**Поведінка без `strict_types`:** PHP намагається привести тип (coercive mode) — `"42"` → `int(42)`. З `strict_types=1` — `TypeError` при неточному типі.

**Навіщо потрібно:**
- Явний контракт функції — документація прямо в сигнатурі
- Ранні помилки в dev замість тихих багів у prod
- Статичний аналіз (PHPStan/Psalm) без type hints практично неможливий
- IDE автодоповнення і навігація по коду

#### Міні-шпаргалка

- Type hint = оголошення типу параметра / return / property
- Перевіряється в runtime; з `strict_types=1` — без coercion
- `?Type` = nullable; `A|B` = union; `A&B` = intersection
- Без type hints PHPStan і IDE «сліпі»

</details>

### 6. Як у PHP передаються змінні: за значенням чи за посиланням, і як це працює на практиці?

<details>
<summary>Розкрити:</summary>

#### Відповідь

За замовчуванням PHP передає **за значенням** — функція отримує копію. Зміни всередині функції не впливають на оригінал. Але є важливий нюанс: PHP використовує **copy-on-write (COW)** — фактичне копіювання відбувається лише в момент зміни, тому передача великого масиву «за значенням» не коштує пам'яті якщо функція його не змінює.

```php
function increment(int $n): int
{
    $n++;        // змінює локальну копію
    return $n;
}

$a = 5;
increment($a);
echo $a; // 5 — оригінал не змінився
```

**Передача за посиланням** — через `&`:
```php
function increment(int &$n): void
{
    $n++;        // змінює оригінал
}

$a = 5;
increment($a);
echo $a; // 6
```

**Об'єкти — окремий випадок.** Об'єкти передаються «за значенням дескриптора» (handle/reference identifier). Функція отримує копію вказівника на той самий об'єкт — тому мутація властивостей видима зовні, але `$obj = new OtherClass()` не замінить зовнішню змінну:

```php
function mutate(stdClass $obj): void
{
    $obj->name = "changed"; // видимо зовні — той самий об'єкт
}

function replace(stdClass $obj): void
{
    $obj = new stdClass(); // НЕ видимо зовні — лише локальний вказівник
}

$o = new stdClass();
$o->name = "original";
mutate($o);
echo $o->name; // "changed"
replace($o);
echo $o->name; // "changed" — replace не вплинув
```

Щоб замінити об'єкт зовні — потрібен `&`: `function replace(stdClass &$obj)`.

#### Міні-шпаргалка

- Скаляри/масиви — за значенням (copy-on-write: копія тільки при зміні)
- `&$param` — за посиланням: зміни видимі зовні
- Об'єкти — передається handle: мутація властивостей видима, але `$obj = new ...` — ні
- `&` для об'єкта — щоб замінити сам вказівник

</details>

### 7. Що таке посилання в PHP і які основні операції з ними існують?

<details>
<summary>Розкрити:</summary>

#### Відповідь

Посилання в PHP — це два імені (змінні) що вказують на одне й те саме місце в пам'яті (один zval). На відміну від C-вказівників, PHP-посилання не є адресами в пам'яті — це aliasi у таблиці символів.

**Створення посилання:**
```php
$a = 10;
$b = &$a;   // $b і $a — одне й те саме значення
$b = 20;
echo $a;    // 20
```

**Посилання у функціях:**
```php
function addSuffix(string &$str): void
{
    $str .= '_suffix';
}

$name = 'file';
addSuffix($name);
echo $name; // 'file_suffix'
```

**Посилання у foreach** — без `&` foreach копіює елемент:
```php
$arr = [1, 2, 3];

foreach ($arr as &$val) {   // зміна оригінального масиву
    $val *= 2;
}
unset($val); // ОБОВ'ЯЗКОВО: $val залишається посиланням на останній елемент

print_r($arr); // [2, 4, 6]
```
Якщо не зробити `unset($val)` після foreach з посиланням — наступна операція що записує в `$val` тихо зіпсує останній елемент масиву. Класична пастка.

**Видалення посилання:**
```php
$a = 10;
$b = &$a;
unset($b);   // видаляє тільки аліас $b; $a = 10 залишається
```

**Коли використовувати:** рідко. Здебільшого посилання вирішують проблему яку краще вирішити поверненням значення або об'єктом. Виправданий кейс — великий масив що функція має змінити без копіювання, або `foreach` з модифікацією елементів.

#### Міні-шпаргалка

- `$b = &$a` — аліас: обидві змінні вказують на одне значення
- `function f(&$x)` — параметр за посиланням
- `foreach ($arr as &$val)` — завжди `unset($val)` після циклу
- `unset($b)` — видаляє аліас, не значення
- Уникати без потреби: повернення значення — чистіше

</details>

### 8. Які прості типи даних підтримує PHP і які особливості їх використання потрібно враховувати?

<details>
<summary>Розкрити:</summary>

#### Відповідь

PHP має 4 скалярних типи, 2 складених, 2 спеціальних і 1 псевдотип:

**Скалярні:**

`int` — цілі числа. Розмір залежить від платформи: 64-bit PHP — `PHP_INT_MAX = 9223372036854775807`. Немає unsigned int. Переповнення → автоматична конвертація у `float`.

`float` — IEEE 754 double precision. Не є точним: `0.1 + 0.2 !== 0.3`. Для грошей — `bcmath`.

`string` — бінарно безпечний рядок байтів. Не Unicode-aware: `strlen("привіт")` повертає кількість байт, не символів. Для Unicode — `mb_strlen`. Рядки в PHP — незмінні (immutable) значення: кожна модифікація створює нову копію (COW).

`bool` — `true`/`false`. Falsy значення: `false`, `0`, `0.0`, `""`, `"0"`, `[]`, `null`. Решта — truthy. Пастка: `"false"` (рядок) — truthy!

**Складені:**

`array` — впорядкований словник (ordered map). Може бути списком (`[1,2,3]`) або асоціативним (`['key' => 'val']`). Внутрішньо — хеш-таблиця + збережений порядок. Передається за значенням (COW).

`object` — екземпляр класу. Передається через handle (дескриптор).

**Спеціальні:**

`null` — відсутність значення. Falsy. Типова пастка: `(int)null === 0`, `(string)null === ""` — мовчазне перетворення.

`resource` — дескриптор зовнішнього ресурсу (файл, з'єднання з БД). Deprecated у нових API на користь об'єктів.

**Псевдотипи (тільки для анотацій):**

`mixed` — будь-який тип; `never` — не повертає; `void` — повертає без значення; `iterable` — array або Traversable.

**Важливі особливості:**

```php
// bool falsy пастки
var_dump((bool)"false"); // true — рядок непорожній!
var_dump((bool)"0");     // false — єдиний непорожній рядок що є falsy

// null coalescing
$val = $arr['key'] ?? 'default'; // безпечно якщо ключ не існує

// int overflow
$big = PHP_INT_MAX + 1;
var_dump(gettype($big)); // "double" — тихо стало float!

// string як масив (доступ по символу)
$s = "hello";
echo $s[0]; // "h"
```

#### Міні-шпаргалка

- `int`: 64-bit signed; overflow → float (тихо!)
- `float`: не точний (IEEE 754); для грошей — bcmath
- `string`: байти, не символи; `mb_*` для Unicode
- `bool`: falsy — `false`, `0`, `""`, `"0"`, `[]`, `null`; `"false"` — truthy!
- `null`: falsy; `(int)null` → 0, `(string)null` → "" мовчки
- `array`: ordered map; передається за значенням (COW)

</details>

### 9. Які підводні камені існують при порівнянні значень у PHP та приведенні типів? Що змінилося в PHP 8 у цьому контексті?

<details>
<summary>Розкрити:</summary>

#### Відповідь

`==` (loose comparison) приводить обидва операнди до спільного типу перед порівнянням. Це джерело несподіваних результатів.

**PHP 7 — найнебезпечніші кейси:**
```php
var_dump(0 == "foo");      // true  — "foo" → int(0)
var_dump(0 == "0");        // true
var_dump(0 == "");         // true
var_dump(0 == null);       // true
var_dump("1" == "01");     // true  — обидва числові рядки → int
var_dump("10" == "1e1");   // true  — наукова нотація
var_dump(100 == "1e2");    // true
var_dump("" == null);      // true
var_dump("0" == false);    // true
var_dump("0" == null);     // false — несиметрично!
var_dump([] == false);     // true
var_dump([0] == [false]);  // true
```

**PHP 8 — виправлені порівняння:**

Головна зміна: порівняння `int == string` тепер перетворює рядок на число (не число на рядок). Якщо рядок не є числовим — порівнюються як рядки.

```php
// PHP 8:
var_dump(0 == "foo");   // false — "foo" не числовий, порівнюються як рядки
var_dump(0 == "");      // false
var_dump(0 == null);    // true  — залишилось
var_dump("" == null);   // true  — залишилось
var_dump("1" == "01");  // true  — обидва числові рядки
var_dump(0 == "0");     // true  — "0" числовий
```

**Таблиця що завжди безпечна — `===` (strict):**
```php
var_dump(0 === "foo");   // false
var_dump(0 === 0);       // true
var_dump("1" === "01");  // false
var_dump(null === false); // false
```

**Приведення типів і пастки:**
```php
(int)"42abc"   // → 42    (мовчки відкидає "abc")
(int)"abc"     // → 0
(int)true      // → 1
(int)false     // → 0
(int)null      // → 0
(bool)""       // → false
(bool)"0"      // → false — єдиний непорожній рядок що є false
(bool)"false"  // → true  — рядок непорожній!
(array)null    // → []
(array)"hello" // → ["hello"]
(array)42      // → [42]
```

**Switch vs match:**
```php
// switch використовує == (loose)
switch (0) {
    case "foo": echo "match!"; break; // спрацює в PHP 7!
}

// match використовує === (strict) — завжди безпечний
match(0) {
    "foo" => "match!", // не спрацює
};
```

#### Міні-шпаргалка

- `==` — loose: приводить типи, повно пасток
- `===` — strict: тип і значення, завжди безпечний
- PHP 8: `0 == "foo"` → `false` (фікс); `0 == ""` → `false`
- `"0"` — falsy; `"false"` — truthy
- `switch` → `==`; `match` → `===`
- Правило: завжди `===`, `match` замість `switch`

</details>

### 10. У чому різниця між одинарними і подвійними лапками в PHP?

<details>
<summary>Розкрити:</summary>

#### Відповідь

**Одинарні лапки `'...'`** — літеральний рядок. PHP не інтерпретує жодних змінних і майже жодних escape-послідовностей. Єдині винятки: `\'` (екранована одинарна лапка) і `\\` (екранований бекслеш).

```php
$name = "World";
echo 'Hello $name';      // Hello $name   — змінна не підставилась
echo 'Tab:\t Newline:\n'; // Tab:\t Newline:\n — escape не спрацював
echo 'It\'s fine';        // It's fine
```

**Подвійні лапки `"..."` — інтерполяція.** PHP розбирає рядок і підставляє змінні та escape-послідовності.

```php
$name = "World";
echo "Hello $name";         // Hello World
echo "Hello {$name}!";      // Hello World! — фігурні дужки для складних виразів
echo "Tab:\t Newline:\n";   // реальний таб і переведення рядка
echo "Price: {$obj->price}"; // метод/властивість об'єкта
echo "Item: {$arr['key']}";  // елемент масиву
```

Основні escape-послідовності в подвійних лапках: `\n`, `\r`, `\t`, `\$` (буквальний `$`), `\"`, `\\`, `\u{1F600}` (Unicode codepoint, PHP 7+).

**Heredoc і Nowdoc** — для багаторядкових рядків:
```php
// Heredoc (як подвійні лапки — інтерполяція є)
$text = <<<EOT
Hello $name,
This is heredoc.
EOT;

// Nowdoc (як одинарні лапки — без інтерполяції)
$text = <<<'EOT'
Hello $name,
No interpolation here.
EOT;
```

**Продуктивність.** Різниця між `'` і `"` без змінних мізерна (PHP оптимізує на етапі компіляції опкодів). Обирати варто за семантикою: немає змінних → одинарні (читабельніше, явно що без підстановок).

#### Міні-шпаргалка

- `'...'` — літерал, без інтерполяції, без escape (крім `\'` і `\\`)
- `"..."` — інтерполяція `$var`, `{$expr}`, escape `\n\t\r`
- Heredoc `<<<EOT` — як `"`, багаторядковий
- Nowdoc `<<<'EOT'` — як `'`, багаторядковий
- Продуктивність: різниця незначна; обирати за читабельністю

</details>

### 11. Що таке variadic functions і splat-оператор у PHP, і в яких випадках вони корисні?

<details>
<summary>Розкрити:</summary>

#### Відповідь

**Variadic function** — функція що приймає довільну кількість аргументів через `...` перед останнім параметром. PHP збирає всі зайві аргументи у масив.

```php
function sum(int ...$numbers): int
{
    return array_sum($numbers);
}

echo sum(1, 2, 3, 4); // 10
echo sum();           // 0
```

Можна комбінувати зі звичайними параметрами — variadic завжди останній:
```php
function log(string $level, string ...$messages): void
{
    foreach ($messages as $msg) {
        echo "[{$level}] {$msg}\n";
    }
}

log('ERROR', 'DB timeout', 'Retry failed', 'Alert sent');
```

**Splat-оператор `...` при виклику** — розпаковує масив або iterable в список аргументів:
```php
function add(int $a, int $b, int $c): int
{
    return $a + $b + $c;
}

$args = [1, 2, 3];
echo add(...$args); // 6 — еквівалент add(1, 2, 3)
```

**Злиття масивів через splat** (PHP 7.4+ підтримує string keys):
```php
$defaults = ['color' => 'red', 'size' => 'M'];
$custom   = ['size' => 'L', 'weight' => '200g'];

$merged = [...$defaults, ...$custom];
// ['color' => 'red', 'size' => 'L', 'weight' => '200g']
// Пізніші ключі перезаписують ранні — як array_merge
```

**Передача named arguments через splat (PHP 8.1+):**
```php
$params = ['separator' => ', ', 'array' => ['a', 'b', 'c']];
echo implode(...$params); // a, b, c
```

**Де корисно:**
- Wrapper-функції що пробрасовують аргументи далі: `call_user_func(...$args)`
- Декоратори і proxy-методи
- Математичні helper-и (sum, max з довільною кількістю)
- Розпаковка результатів `array_map`, `array_filter` в параметри

#### Міні-шпаргалка

- `function f(int ...$args)` — variadic: зайві аргументи → масив `$args`
- `f(...$array)` — splat при виклику: розпаковує масив в аргументи
- `[...$a, ...$b]` — злиття масивів (PHP 7.4+)
- Variadic завжди останній параметр; може мати type hint
- Замінює застарілий `func_get_args()`

</details>

### 12. Що таке інкремент і декремент у PHP, і в чому різниця між префіксною та постфіксною формою?

<details>
<summary>Розкрити:</summary>

#### Відповідь

`++` і `--` збільшують/зменшують значення змінної на 1. Різниця між префіксною і постфіксною формою — **коли повертається значення**.

**Префіксна (`++$a`)** — спочатку змінює, потім повертає нове значення:
```php
$a = 5;
echo ++$a; // 6 — спочатку +1, потім вивід
echo $a;   // 6
```

**Постфіксна (`$a++`)** — спочатку повертає поточне значення, потім змінює:
```php
$a = 5;
echo $a++; // 5 — спочатку вивід, потім +1
echo $a;   // 6
```

Практичний приклад де різниця важлива:
```php
$i = 0;
$arr[] = $i++; // $arr[0] = 0, потім $i = 1
$arr[] = ++$i; // $i = 2, $arr[1] = 2

// У while-умові:
while ($n-- > 0) { /* виконується $n разів, потім $n = -1 */ }
while (--$n > 0) { /* виконується $n-1 разів */ }
```

**Особливості PHP інкременту (відрізняються від C):**

`null` і `false` — `++` не впливає; `--` теж не впливає:
```php
$a = null;
$a++;
var_dump($a); // int(1) — null → 1 при ++

$b = false;
$b++;
var_dump($b); // bool(false) — false не змінюється!
```

Рядки — PHP підтримує Perl-подібний інкремент рядків (до PHP 8.3):
```php
$s = 'a';
$s++;
echo $s; // 'b'

$s = 'z';
$s++;
echo $s; // 'aa'

$s = 'Az';
$s++;
echo $s; // 'Ba'
```
У PHP 8.3 поведінку інкременту нечислових рядків deprecated — краще не покладатись на це.

Декремент рядків — не змінює (на відміну від C):
```php
$s = 'b';
$s--;
echo $s; // 'b' — без змін
```

#### Міні-шпаргалка

- `++$a` — префікс: змінює і повертає нове значення
- `$a++` — постфікс: повертає поточне, потім змінює
- `null++` → `int(1)`; `false++` → `false` (без змін)
- Рядковий `++` ('a'→'b', 'z'→'aa') — Perl-стиль, deprecated у 8.3
- У простих циклах різниця незначна; важлива лише коли значення використовується в тому ж виразі

</details>

### 13. Чим відрізняються оператори break і continue?

<details>
<summary>Розкрити:</summary>

#### Відповідь

**`break`** — повністю завершує виконання поточного циклу (або `switch`) і передає керування коду після нього.

**`continue`** — пропускає решту поточної ітерації і переходить до наступної (до умови перевірки в `while`/`for`, до наступного елемента в `foreach`).

```php
for ($i = 0; $i < 5; $i++) {
    if ($i === 3) break;    // зупинитись на 3
    echo $i;                // 0 1 2
}

for ($i = 0; $i < 5; $i++) {
    if ($i === 3) continue; // пропустити 3
    echo $i;                // 0 1 2 4
}
```

**Числовий аргумент** — `break N` і `continue N` діють на N рівнів вкладеності:

```php
for ($i = 0; $i < 3; $i++) {
    for ($j = 0; $j < 3; $j++) {
        if ($j === 1) break 2;    // виходить з обох циклів
        echo "$i:$j ";
    }
}
// 0:0

for ($i = 0; $i < 3; $i++) {
    for ($j = 0; $j < 3; $j++) {
        if ($j === 1) continue 2; // пропускає до наступної ітерації зовнішнього циклу
        echo "$i:$j ";
    }
}
// 0:0 1:0 2:0
```

**`break` у `switch`** — обов'язковий щоб не «провалитись» у наступний `case`:
```php
switch ($status) {
    case 'active':
        doActive();
        break;   // без break — виконається і 'inactive' теж
    case 'inactive':
        doInactive();
        break;
}
```
`match` не має цієї проблеми — завжди виконує тільки один arm.

#### Міні-шпаргалка

- `break` — вихід з циклу/switch повністю
- `continue` — перехід до наступної ітерації
- `break 2` / `continue 2` — діє на N рівнів вкладеності
- `break` у `switch` — обов'язковий для запобігання fall-through
- `match` не потребує `break`

</details>

### 14. Що таке copy-on-write у PHP і як це впливає на роботу зі змінними та масивами?

<details>
<summary>Розкрити:</summary>

#### Відповідь

**Copy-on-write (COW)** — оптимізація PHP: при присвоєнні або передачі значення фактична копія не створюється одразу. Обидві змінні вказують на той самий zval (внутрішня структура значення). Копія відбувається тільки в момент **запису** в одну з них.

```php
$a = range(1, 100000); // великий масив — 1 zval
$b = $a;               // копії немає! $b і $a — спільний zval, refcount=2

// Ніякої пам'яті не витрачено на копіювання

$b[] = 999999;         // ось тут PHP робить реальну копію $a → $b
                       // $a не змінився
```

**Навіщо це важливо:**

```php
function process(array $data): int
{
    return count($data); // читаємо — копії немає, COW тримає спільний zval
}

function modify(array $data): array
{
    $data[] = 'new';    // записуємо — тут відбувається копія
    return $data;       // оригінал не змінився
}

$arr = range(1, 100000);
process($arr);  // дешево — без копіювання
modify($arr);   // копія відбувається всередині modify при першому записі
```

**COW і посилання.** Якщо змінна стала посиланням (`$b = &$a`) — COW відключається для цього zval: будь-яка зміна через будь-який аліас одразу видима всім.

**Практичний наслідок для продуктивності:**

Передача великого масиву у функцію за значенням — дешева операція якщо функція тільки читає. Якщо функція модифікує масив — копія відбувається при першій зміні. Тому немає сенсу передавати великі масиви за посиланням (`&$arr`) «для економії пам'яті» якщо функція і так не змінює масив — COW вже це оптимізує.

**Внутрішній механізм:** кожен zval має `refcount` (лічильник посилань). При присвоєнні `$b = $a` → `refcount=2`. При запису в `$b` → PHP бачить `refcount > 1`, робить копію, знижує refcount оригіналу до 1, модифікує нову копію.

#### Міні-шпаргалка

- COW = реальна копія тільки при записі, не при присвоєнні
- `$b = $a` → спільний zval; `$b[] = x` → тут копія
- Передача масиву у функцію за значенням — дешева якщо функція тільки читає
- Посилання (`&`) відключають COW — всі аліаси бачать зміни одразу
- Немає сенсу передавати `&$arr` «для економії» якщо функція не змінює масив

</details>

### 15. Що таке стек і купа в контексті роботи програми, і як це пов'язано з виконанням PHP-коду?

<details>
<summary>Розкрити:</summary>

#### Відповідь

**Стек (stack)** — область пам'яті LIFO для виконання функцій. При кожному виклику функції на стек кладеться **stack frame** зі: збереженою адресою повернення, локальними змінними, параметрами, проміжними значеннями. При поверненні з функції frame знімається. Стек обмежений у розмірі (зазвичай 1–8 MB).

**Купа (heap)** — динамічна область пам'яті для об'єктів і структур що живуть довше одного виклику функції. Управляється алокатором (malloc/free на рівні C); розмір значно більший (обмежений `memory_limit` в PHP).

**У контексті PHP:**

PHP як інтерпретована мова має два рівні стеку:

*C-стек* (стек процесу) — використовується рушієм Zend: stack frames PHP-функцій транслюються у C-виклики всередині рушія. Нескінченна рекурсія = переповнення C-стеку = `Segmentation fault` (не catchable).

*PHP call stack* — логічний стек PHP-викликів що PHP відстежує для `debug_backtrace()`, exception stack traces, Xdebug. Це та інформація що бачить розробник.

```php
function a(): void { b(); }
function b(): void { c(); }
function c(): void {
    $trace = debug_backtrace();
    // Stack: c → b → a → {main}
    throw new RuntimeException("error");
}

// Exception повідомлення містить stack trace — це PHP call stack
```

**Купа в PHP** — всі об'єкти, масиви, рядки, zval-структури живуть у купі. PHP управляє пам'яттю через reference counting (refcount) + cycle collector для циклічних посилань.

**Stack overflow у PHP:**
```php
function recurse(): void { recurse(); }
recurse();
// Fatal error: Maximum function nesting level of '256' reached
// (xdebug обмежує; без xdebug — segfault)
```

PHP не має вбудованого обмеження глибини стеку без Xdebug — рекурсія впирається в C-стек процесу.

**Fibers (PHP 8.1)** — кооперативні "зелені нитки" зі своїм стеком у купі. Кожен Fiber має власний C-стек виділений у heap, що дозволяє призупиняти і відновлювати виконання.

#### Міні-шпаргалка

- **Стек**: LIFO, stack frames при виклику функцій; обмежений розмір
- **Купа**: динамічна пам'ять для об'єктів/масивів; більша, управляється алокатором
- PHP має C-стек (рушій) і логічний PHP call stack (backtrace)
- Об'єкти, масиви, zval — у heap; управляються refcount + GC
- Нескінченна рекурсія → C-стек overflow → segfault або fatal error
- Fibers (8.1) — власний стек у heap для кожного fiber

</details>
